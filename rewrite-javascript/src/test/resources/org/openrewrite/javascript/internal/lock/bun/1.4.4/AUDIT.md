`1.4.4+38afee6c8`; the tag resolves to `38afee6c84fcf48c0edb2466aa4b27d287a59c30`.

## Changes outside the reproduced operation

`cache_pack.rs`, `cache_publish.rs`, and `prune.rs` add cache pack/unpack/prune and package pruning commands.
The engine reproduces an install over a supplied text lock, not those commands or a filesystem cache.
Cache-format changes and HTTP retry/backoff changes do not determine the text lock's bytes from the supplied
manifests/registry responses. Physical stale-copy cleanup, hardlink/copy fallback and lifecycle process changes
are exercised by real frozen and normal full installs; they are not simulated by the lock engine.
Yarn Berry migration, npm-shrinkwrap migration, `bun add`/`update` writeback, publish, bunx, and new CLI-only
commands are not entered when regenerating an existing bun.lock. Missing git/tarball contents, missing host inputs,
foreign-lock migration and manifest-arrival ambiguity retain the engine's explicit failure behavior.

This audit does not turn fixture success into a claim that arbitrary Bun commands or unknown network/filesystem
state are reproducible. The release gate names the install paths this engine can reproduce or explicitly decline.

## Recordings and reruns

The external fixture checkout used by these tests is openrewrite/rewrite-javascript-lock-fixtures at
`a2891e010709778a8406349cafe4e95d6f869648`. The `lock/bun/bun144-*` resources contain actual Bun 1.4.4 output,
never hand-edited output locks. `pkg-before`, `pkg`, config and tree files are inputs. The existing fixture
recorder can recreate a recording with Bun 1.4.4 on PATH:

```
bash <fixtures>/record/record-bun-open.sh <scenario-directory>
```

The twelve scenarios copied from the existing corpus were run by `record/sweep/sweep-bun.js` against that
scenario's frozen registry. Their `about` and `recorded-with` files retain this provenance. The semver table is
regenerated by running `generate/bun-1.4.4-semver.js` with Bun 1.4.4.

Run `:rewrite-javascript:test --tests '*internal.lock.bun.*'` for the offline corpus, round-trip and resolver tests.
Run the scenario tests with `REWRITE_LOCK_EVERY_RELEASE=1` to retain the old release matrix.

Real-project acceptance uses the original LSTs, without overriding NodeRuntime, and these exact source commits:

- nozomio-labs/nia-cli: `3ebf0b0bb62ff6a73d630232b2b03c8bde30fe86`
- kovrichard/catalyst: `e600749798151d128ac83a817662ee4feec994de`

Both `UpgradeDependencyVersion(typescript, 7.0.2)` and
`UpgradeTransitiveDependencyVersion(ms, 2.1.3, null)` must produce manifest and lock patches that apply cleanly.
For each patch, run Bun 1.4.4 frozen full install, normal lock-only install, and normal full install, with scripts
disabled. Every command must succeed and leave bun.lock byte-identical to the generated lock.
The handoff archive on the changeset board includes the replay harness, scripts, patches, raw sweep results,
real-install logs and hashes, so this acceptance can be rerun independently without building consumer LSTs.
