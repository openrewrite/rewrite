# Remove unused subtype imports after replacing constants

## Problem
`ReplaceConstantWithAnotherConstant` removes the import of the constant's declaring type, but not of the type written in the source. Hibernate declares `JACC_CONTEXTID` on the interface `AvailableSettings`, and code writes `Environment.JACC_CONTEXTID` (`Environment implements AvailableSettings`), so replacing it leaves an unused `import org.hibernate.cfg.Environment;`.

While testing that, `RemoveImport` turned out to delete or unfold a static wildcard import that still supplies a nested type used by simple name (`import static java.util.Map.*;` with `Entry<K, V>`), which breaks compilation.

## Solution
- `ReplaceConstantWithAnotherConstant` also asks to remove the import of the written qualifier type; it stays when something else uses it.
- `RemoveImport` counts nested types supplied by a static wildcard, ignoring those already visible through inheritance or a single import, in the same pass that collects names.
