# Allow XML documents to have no root element

## Problem
The XML parser already produces documents with only a prolog (an empty file, a directive-only JSP, a comment-only configuration file), but `Xml.Document.getRoot()` is declared non-null. Recipes that dereference it throw a `NullPointerException`; a downstream migration recipe running on a large real application got 218 error markers from JSP files this way and had to guard every call.

## Solution
- Mark `Xml.Document.root` `@Nullable` (Java and C#) and document when it is absent.
- Make the callers that need an element handle its absence: `SemanticallyEqual` compares prologs of rootless documents, `Xml.Tag.build` reports malformed input and a missing element clearly, `XsltTransformationVisitor` keeps returning a rootless document, `MavenVisitor` skips resolved POMs without a root, `AddDevelocityMavenExtension` does not half-apply on a rootless `.mvn/extensions.xml`.
- C# `Document.Root` is now `Tag?`; its visitor and project scanner handle a missing root.

API note: under JSpecify `@NullMarked`, Kotlin code such as `document.root.children` needs a safe call, and C# built with warnings as errors needs a null check.

## Context (not for the PR body)
Found while building the Hibernate 3.6 to 4.3 migration recipes (moderneinc/rewrite-hibernate, branch hibernate-4x-steps). There, the null guards in `HibernateSettings.surface()` and `MigrateHbmMappings` stay: with this change they become the type-correct check rather than a workaround. Tests: rewrite-xml 390, rewrite-maven 1,738, Java 25 TCK 707, rewrite-csharp JVM 70 + integTest 32, C# xUnit 3,096 (all green, the 5 host-only iOS-pack failures are pre-existing).
