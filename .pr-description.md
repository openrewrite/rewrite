# Recognize class references in Spring and servlet XML

## Problem
`ChangeType` and `ChangePackage` update class names in XML through reference providers. The Spring provider only looks at schema-based bean files and a few attributes, so a rename leaves the old class name in DTD-based bean files, `<prop>` values, `value=` attributes on `property`, `entry` and `constructor-arg`, class-valued map keys, and in servlet descriptors (`filter-class`, `servlet-class`, `listener-class`, `exception-type`). The application then fails at startup with a `ClassNotFoundException`.

## Solution
- Spring provider: accept Spring beans DTDs (public ids and the system ids Spring's `BeansDtdResolver` accepts), namespace-prefixed beans elements and `util:properties`, resolve the in-scope namespace so foreign elements (Spring Security, Camel) are not matched, and expose qualified class names in `prop` text and keys, `entry` keys and values, `property`/`constructor-arg` values, with the same qualified-name rule the properties and YAML providers use.
- New servlet descriptor provider for `web-app` and `web-fragment` roots in any `.xml` file.

## Context (not for the PR body)
Found while building the Hibernate 3.6 to 4.3 migration recipes (moderneinc/rewrite-hibernate, branch hibernate-4x-steps): `MoveSpringOrmHibernate3BeanClasses` re-implements these forms to move Spring `orm.hibernate3` classes and can shrink to its warnings once this lands. Skipped on purpose: package-valued properties (`packagesToScan`), sharing the qualified-name heuristic across modules in rewrite-core. Tests: rewrite-xml 394, rewrite-java-test 2,650, Java 25 TCK 707, all green.
